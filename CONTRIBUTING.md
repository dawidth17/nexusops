# Contributing

Development is done using short-lived branches.

Branch examples:

- `feat/...`
- `fix/...`
- `chore/...`

Changes should be tested before being merged into `main`.

Larger architecture changes should be documented in `docs/adr`.

Secrets and local environment files must not be committed.

## Definition of Done

A task is done when:

- the expected behavior works;
- relevant tests pass;
- no secrets or generated files are committed;
- documentation is updated when needed;
- the change is reviewed and merged into `main`.
